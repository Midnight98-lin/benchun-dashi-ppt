# 运行、编辑与导出

本技能是独立品牌扩展，采用 Dashi 式 `layout + props` 编排思想，但未复制原 Dashi 源码、主题包、专有浏览器编辑器或私有导出 API。HTML 编辑与本地服务独立实现；PPTX 使用平台 `@oai/artifact-tool`，不是 Dashi 官方附加主题。

## 环境与边界

Node 20+；HTML 初次生成与本地服务使用 Node 内置模块。HTML 嵌入素材 data URL，可离线打开。Python 正文核对仅用标准库。PPTX 导出需要 `@oai/artifact-tool` 与 `presentations` 技能的终检工具；若平台提供 `load_workspace_dependencies` 则用其定位运行时，否则检查本机已有依赖和用户配置，不调用不存在的工具。必要时设置 `BENCHUN_NODE_MODULES`、`PRESENTATIONS_SKILL_DIR`、`RUNTIME_PYTHON`。缺少依赖时说明缺项，不切换为整页截图 PPT。跨 AI 能力和分格式终审边界见 `dual-review.md`。

本地 PDF 导出使用 Playwright 驱动 Edge 按打印版式生成每页 16:9 的静态 PDF；需要相应浏览器与运行时。离线模式可直接调用浏览器打印。PDF 不保留可编辑演示对象；这里也不是通用 PPTX 浏览器导入器。

## 默认入口（占位路径须替换为当前绝对路径）

```powershell
node <skill-root>/scripts/render.mjs <task>/goal.json <task>/presentation
node <skill-root>/scripts/serve.mjs <task>/presentation --port 5368
```

首次 `render` 在本次任务目录生成 `scene.json` 与独立 `index.html`；`serve` 通过单个本地端口提供编辑器、保存与导出。打开终端实际返回的 `http://127.0.0.1:5368` 地址；端口冲突时换空闲端口，不停掉无关进程。Windows 后台启动服务时使用隐藏窗口，不主动暴露到外网。不要把本地地址当成可分享给别人的公网网址。

默认交付 HTML 演示并打开本地编辑入口；用户明确仅要 PPTX 时可以只交 PPTX。后台服务必须实际存活，交付时交代保存方式及服务关闭后的限制。

## 保存模型与修改主稿

- `goal.json` 是初次编排与来源记录，原稿和原始 goal 保持不动。进入浏览器人工编辑后，已保存的 `scene.json` 是后续编辑、演示与导出的主稿，不能重跑旧 goal 或读取旧源工作簿覆盖它。
- 在线编辑器支持文字、字体、位置尺寸、图片、表格和图表修改，以及页底色、新增文字、插入图片、添加形状、复制/删除与图层调整；文字、形状和图片还共用右侧“自由变形”区，可旋转、水平/垂直翻转和重置。这些修改均进入同一 scene 和撤销/重做记录。自动保存与手动保存写入该演示目录。确认界面显示保存成功后再刷新；保存失败不应被描述为已写盘。
- 修订号用于防止旧页面覆盖新保存。遇到多标签页或并发修订冲突，停止覆盖，先保留未保存稿，再载入最新版本并按用户意图合并；不盲目强制重试旧 scene。
- 导出任务使用启动时已保存 scene 的修订快照；先完成保存，记录该修订与导出结果的对应关系。导出过程中又有修改时，该导出仍属于旧快照，需要新稿则再次保存导出。
- 图片替换仍须保留来源、SKU 与包装核验；浏览器能改数据和文字，不等于助手获得改写授权。用户明确变更应单独记入锁字/数据差异记录，不删掉原始来源。

## 页底色、对象与文字样式

编辑器确认版（2026-09-09）使用银白与森林绿三栏界面，右侧“样式／排列／页面”标签按上下文组织属性。自由变换是展开式浮层，不常驻占用属性面板；折叠与浮层轻动效遵循减少动态效果设置。界面外观不等于课件内容的固定版式。

页底色写入当前页的 `slide.background`，不改变整套品牌色，也不是新增一个覆盖内容的矩形。文字、图片与基本形状作为独立对象加入当前页，可复制、删除、调整前后层级并撤销/重做；操作后仍检查遮挡、阅读顺序和安全边距。矩形本身就是形状，编辑器不另设“色块”入口。

新增图形使用 `type: "shape"`。保存字段如下：

| 字段 | 支持范围 |
| --- | --- |
| `geometry` | `rect`、`roundRect`、`ellipse`、`triangle`、`rightArrow`、`line`；`line` 为水平线 |
| `x/y/w/h` | 画布内的位置与尺寸，单位 px |
| `fill` | 十六进制颜色或 `none`（无填充） |
| `stroke` / `strokeWidth` | 十六进制颜色或 `none`（无描边）；描边粗细 0–20 px |
| `r` | 圆角半径（px）；圆角矩形通过滑块或数字输入调整，0 为直角，有效上限为 `min(360, w/2, h/2)` |

旧 `type: "rect"` 继续按原格式读取，不批量迁移。用户需要描边或无填充时，可将该对象转为 `shape`；除明确修改的属性外，保留原位置、尺寸、样式及层级，不能顺带重排其它对象。

编辑旧圆角矩形的半径时转换为 `shape / roundRect`；即使改为 0，重新选中后仍保留圆角调节入口。圆角修改同步 SVG 显示、保存与撤销/重做，PDF按同一画面打印，PPTX导出到原生圆角矩形参数。改变对象宽高后控件上限随短边更新；不同导出引擎仍需视觉核对。

“插入图片”从本机选择 PNG、JPEG 或 WebP，每张不超过 15 MB；成功后以新的 `type: "image"` 对象加入当前页最上层，默认完整显示并按原始宽高比缩放到画布内。用户可继续调整位置、尺寸、图片适配与图层，不替换已有图片。插入时写入文件名和“用户在编辑器中插入”来源标记；包装图仍需核对真实 SKU 和标签，不因上传成功自动视为包装核验通过。

文字样式按整个文本对象设置：`font`、`size`、`color`、`align`，以及布尔值 `bold`、`italic`、`underline`。字体菜单提供当前系统已核验的 Microsoft YaHei（微软雅黑）、SimSun（宋体）、SimHei（黑体）、DengXian（等线）、Arial、Georgia。该菜单不表示其它机器已安装字体；移动设备或另一台电脑需要相应字体，不承诺自动下载或嵌入。含中文时检查缺字、字体回退与换行，斜体/下划线也需检查实际渲染。

## 自由变形

文字、图片、`rect`与`shape`共用右侧“自由变换”按钮；默认收起，点击后向画布侧展开浮动组件，不占右侧属性栏高度。点击外部、关闭按钮或 Escape 收起；切换对象或页面也收起。窄屏时面板保持在可视范围内。组件包含 PS 基础自由变换操作：九点参考位置、W/H 百分比、宽高比例锁定、放大/缩小按钮、八个画布缩放控制点、旋转角度、左右转90°、双向翻转。100% 以本次选择对象时的尺寸为基准；缩放直接更新原生 `x/y/w/h`，文字高度缩放同步调整字号（8–160 px），解锁宽高后文字可能重新换行，图片仍遵循完整显示/铺满适配。所有操作纳入保存、撤销与重做。

拖动控制点默认锁定比例；Shift 临时切换比例锁定，Alt 固定中心，对角点/对边作为普通拖动的固定位置。旋转后按对象局部坐标缩放；翻转状态保留。松开鼠标或 Enter 完成拖动，Escape/指针取消撤回本次拖动。超出当前画布尺寸或字号范围时停止扩大，不产生无法保存的场景。九点参考位置用于右侧百分比及按钮缩放。

旋转与翻转共用字段为 `rotation`（-180°至180°）、`flipHorizontal`、`flipVertical`；以对象框中心为原点。“重置旋转与翻转”只清除角度和翻转状态，尺寸通过缩放或撤销调整。

HTML、打印PDF和PPTX均须保留旋转与翻转。PPTX中文字和形状继续是原生对象，图片继续是独立图片对象。这里的“自由变形”不包括透视扭曲、四角逐点变形、斜切或3D旋转；不要用浏览器近似效果冒充可在PowerPoint中保真的功能。

这些功能仍不包括逐字富文本、任意自定义图形或新增页面。新增内容必须来自用户授权；删除对象不等于获准删除原文、证据或正式资产。底色和图形样式仍服从本纯正式视觉与包装规则。

## 离线 HTML 与恢复

离线打开 `index.html` 可编辑并演示，但浏览器不能直接覆盖磁盘原文件，在线自动保存也不适用于离线页面。每次修改后须下载编辑后的 HTML；重新打开下载文件核对修改与图片仍在。关闭或刷新前未下载的修改不能视为已保存。

将下载的 HTML 恢复为本地可保存演示时，目标必须是全新目录：

```powershell
node <skill-root>/scripts/serve.mjs <new-task>/presentation --import-html <downloads>/edited.html --port 5368
```

导入读取嵌入 scene，保留人工修改；不覆盖原 HTML、原 goal 或已有演示目录。离线 HTML 可打印 PDF；PPTX 导出需通过本地服务或下列 CLI。不要提示用户在离线页面等待服务端导出。

## 从已保存 scene 导出

浏览器入口与 CLI 必须使用同一保存模型；不得为了导出重建旧模板。点击导出后，等界面显示生成成功，再点击“下载导出文件”链接保存；生成成功不会自动开始下载。PPTX 先生成候选稿，再通过强制终检生成独立交付文件：

```powershell
$env:BENCHUN_NODE_MODULES = '<bundled-node-modules>'
node <skill-root>/scripts/export-pptx.mjs <task>/presentation/scene.json <task>/candidate.pptx
node <skill-root>/scripts/finalize.mjs <task>/candidate.pptx <task>/delivery/final.pptx --literal-workbooks --scene <task>/presentation/scene.json
python <skill-root>/scripts/text_lock.py verify <task>/text-lock.json <task>/delivery/final.pptx
node <skill-root>/scripts/export-pdf.mjs <task>/presentation/scene.json <task>/candidate.pdf
```

`finalize.mjs` 调用平台包结构、几何、字体和再导入校验；浏览器 PPTX 导出同样必须经过此步骤，失败不得把候选稿标为可交付。验证输出与私人 QA 放任务目录，不混进正式交付文件夹。脚本成功不等于视觉通过，最终 PPTX / PDF 仍须逐页渲染查看。

可选参数 `--scene scene.json` 从该 scene 的文本、表格和图表实际使用字体（未设置对象字体时取 scene 默认字体）建立字体检查集合。本地服务自动传入导出快照；手动 CLI 也应传入与候选 PPTX 相同修订的 scene，不用另一个仍在编辑的稿件。省略此参数保留旧的 Microsoft YaHei 检查方式，不能据此认定新增字体已检查。字体检查不证明字体已嵌入，也不代替目标设备的显示核验。

`--literal-workbooks` 仅用于数据完整的原生图表，嵌入对应已保存 scene 的 Excel 数值快照；本模板 JSON 数据适用。快照不保留外部公式。用户要求原 Excel 与公式时需单独处理源工作簿保全，不能用快照冒充或重新载入旧数据抹掉手工修改；若公式与人工值不能同时保全，先说明冲突。

PPTX 文字、形状、图表、表格保持原生可编辑，新增图形的填充/描边、文字的字体/斜体/下划线，以及文字/形状/图片的旋转与翻转应保留；插入图片与实拍背景、产品图仍是图片对象，页面纯色背景是页属性。不得把新增对象烘焙成整页截图。HTML 与 PPTX 共用 scene 几何和数据，但不同引擎的字体、图表绘制、图片组合可能稍有差异，必须检查最终渲染及对象可编辑性。PDF 保留静态外观，不提供这些对象的编辑能力。样张数字只作“模板演示”，不是本纯产品事实。

## 验证与故障边界

按 `qa-checklist.md` 在任务副本测试：在线保存/刷新、并发冲突、离线下载/重开/新目录导入、同一修订的 PPTX / PDF 导出，以及文字、字体、位置、图片、表格和图表修改的保真。通过测试须有实际结果，未运行项明确标注；不能仅凭 UI 按钮或导出进程成功声称全部功能可用。运行时、浏览器或字体环境更新后重测相关链路。

新增对象、底色及文字样式另按 `qa.md` 逐项覆盖，尤其是插入图片、六类图形、透明填充与描边、图层顺序、混合字体和斜体/下划线在保存往返及最终文件中的保全；本说明列出功能契约与验收要求，不代表新增链路已经全部实测。

保存冲突、依赖缺失、导出失败或图文溢出时保留当前 scene 与错误信息，在当前任务范围内修复；不重置用户修改、不覆盖源文件、不跳过终检。解决不了的项目说明具体限制与已保全的文件。
