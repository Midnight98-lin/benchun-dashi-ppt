# 双技能画面终审（PPT 适配协议）

此协议是本纯 PPT 制作的必经交付门，不是可选建议。适用于本技能生成或美化的 HTML 演示及所交付 PPTX / PDF。只有实际检查并通过的版本可以称为终稿。仅安装技能、列出检查项、导出成功或检测器零报错，都不等于画面通过。

## 自包含入口

所有路径相对于本技能根目录，不依赖制作者电脑上的私有仓库，也不要求另装这两个技能：

- Taste：`review-skills/design-taste-frontend/SKILL.md`（完整规则）。
- Impeccable：`review-skills/impeccable/SKILL.md`；日常交付终审读取其 `reference/polish.md`。需要独立 UX 批评报告时才走 `reference/critique.md`，不能将本协议的终审冒称完整 critique 命令。
- Impeccable 脚本基目录是 `review-skills/impeccable`，其文档中的 `.agents/skills/impeccable` 路径须解析为这个实际目录，不是用户机器的固定安装路径。
- 开始任务时主 AI 完整读取以上两份 SKILL 和适用参考；Impeccable 的 context 脚本每会话运行一次。缺 Node 时如实记录脚本未执行，以本次简报、品牌规范、源稿和实际画面做人工审查，不伪造脚本成功。

本包默认关闭 context 的联网更新检查及对应用户目录缓存写入。只在当前进程设置 `IMPECCABLE_NO_UPDATE_CHECK=1` 后运行，不修改用户永久环境或项目配置。例如 PowerShell：`$env:IMPECCABLE_NO_UPDATE_CHECK='1'; node <skill-root>/review-skills/impeccable/scripts/context.mjs --target <task>/presentation/index.html`。只读审阅技能、权限不足或没有执行工具时可静态读取并记录未执行原因；不要为了检查协议本身初始化 DESIGN.md、开启 hooks 或生成画面。

## 跨 AI 能力检查

| 实际能力 | 可执行范围与限制 |
|---|---|
| Node 20+ | 本包 HTML 生成和本地编辑服务，不代表有 PPTX 导出、Python 或看图能力 |
| Python 标准库 | `text_lock.py extract/verify` 可核对 PPTX 内其支持的可提取正文；它不支持把 HTML/scene 当 PPTX 传入 |
| 只有 HTML 输出 | 应对有效锁字记录和当前 scene/HTML 的文字、表格与图表标签执行适用的实际程序比对，记录使用工具和覆盖范围；现有 `text_lock.py verify` 不是此入口。没有等效比对工具时保留未完成状态，不能以目视或场景生成成功冒充程序通过；若用户明确接受人工降级，单独标注，不声称全部门槛通过 |
| 没有平台依赖查询工具 | 读取运行手册并检查本机已有依赖/用户配置；不调用不存在的 `load_workspace_dependencies`，不凭空假定专有导出包存在 |
| 没有最终格式渲染器/视觉读取能力 | 该格式不能完成画面终审；其他格式可独立检查、独立报告，候选不得冒充终稿 |

不能自动忽略手写页码或分页后新加的重复标题。把用户授权变更单独映射并比对，原锁字记录仍保留；表格、图表、图片内文字和程序未覆盖项另行标明核验范围。

## 范围和冲突处理

两套原技能是网页设计技能，本包保留原文件并用本协议明确静态演示的适用边界。本次用户要求、原文锁定和本纯正式视觉规范优先；工具、安全和授权边界不被覆盖。

| 原技能场景 | 本纯 PPT 应用方式 |
|---|---|
| 反模板、构图、层级、图文关系、间距、对比度 | 必查，落实到每一页实际画面和全套节奏 |
| 删短标题、限制英文词数、重写生硬表达、破折号禁用 | 不得因此改原文、标点、引文、原有标题或解释层级。用布局及获准分页解决，内容疑问另列，不静默纠错 |
| 假精确数字或“过于整齐”的数字 | 禁止编造；有来源的原数字完整保留，不为设计改成其他数字 |
| 更换默认配色/字体、全页同一深浅主题、强制双主题 | 本纯固定品牌色、中文字体系及已确认深浅章节节奏优先，不另造品牌风格 |
| Hero 两行、眼眉数量、三卡禁令、版式仅用一次 | 作为避免机械重复的提示，不硬套网页配额。以可读、逻辑和整套节奏判断，不删除内容或强行求异 |
| 图形、表格、科学关系图 | 允许准确的原生矢量、连接线和可编辑图表；不能以“禁止手绘 SVG”为由换成照片或删除表格 |
| 必须生图、必须放照片 | 根据内容需要。产品用真实对应 SKU 的包装保真二次渲染；现有合格场景可复用。不生成证书、专利、实验截图或假产品界面 |
| React / Next / 新设计系统 / npm 安装 | 普通 PPT 任务不适用，保留现有 HTML / scene / 导出运行链路 |
| CTA、表单、登录、SEO、手机单列、网站双主题、Web Vitals | 静态页不存在时标 N/A 并说明；不能用这些理由跳过该页视觉检查。修改浏览器编辑器时才审其实际交互、响应和性能 |
| 文档初始化、hooks、pin、doctor、联网生图后备 | 不因制作 PPT 自动改用户工程配置、安装钩子或动用收费 API；按实际任务及授权执行。缺 DESIGN.md 不阻挡使用已存在的品牌规范 |

## 制作与审查顺序

1. **按要求设计制作**：锁定原文与有效用户修订，建立原页/段落到新页映射；说明受众、媒介和设计判断，按本纯模板、包装与数据规则完成全套候选。普通静态演示不额外加网页动效。
2. **保存并渲染候选**：冻结本次已保存 `scene.json` 修订和哈希。生成 HTML 全页截图及联系表；需要 PPTX / PDF 时先内部导出候选并逐页渲染。这是内部检验文件，不是已经通过的用户终稿。
3. **Taste 画面审查**：先联系表判断品牌统一、章节深浅和构图节奏，再逐页判断阅读焦点、布局是否机械、产品是否真实融入场景、配图是否说明本页内容、专业图解和数据是否有表现力而不失真。不要只看封面/抽样八页。
4. **Impeccable 精修审查**：同一修订逐页按 polish 检查字阶、基线、组内/组间间距、换行、行距、光学对齐、图片裁切、页码/目录、对比度及目标屏幕可读性。100% 检查所有页面，关键包装、证据和小字局部 200% 与源资产并排核验。文字保全与几何检测另行运行，不能代替看图。
5. **批量修复与确认**：两次审查先收齐问题，再集中修复一批；重新渲染受影响页面，同时确认全套联系表和文字映射。每轮最多一次初查加一次确认，避免无限微调。确认仍有缺陷则停在“待修复”，列明剩余项和原因，不因轮次用完自动通过；必要时向用户请求影响范围/素材/权限的决定。
6. **通过后交付**：HTML、PPTX、PDF 按各自实际核验情况分别报告；正式链接指向已审查修订。人工编辑、新增页或再次导出造成变化时，受影响部分的通过记录失效，必须重新核对。导出造成字体/几何/图片差异的最终格式也必须看图，不拿 HTML 通过替代 PPTX 通过。

## 双技能不等于必须两个代理

主 AI 必须使用两套技能，不能只跑一个后把另一个打勾。有可用且获准的设计子代理时可分工，主 AI 汇总并终审；无子代理时，同一 AI 先完成并记录 Taste 判断，再做独立的 Impeccable 检查，记录“单 AI 双技能审查”，不得声称双代理。若用户另外要求完整 Impeccable critique，则遵循该命令的代理、检测、报告及降级规则。

## 记录与放行条件

在任务目录填写 `dual-review.md`（格式自由，但至少包含下列信息）：

- 源稿和有效锁字记录；scene 修订号/哈希；各输出文件及实际渲染截图路径。
- 审查者/实际技能入口/日期；单 AI 或多代理；目标展示尺寸与已检查格式。
- 逐页表：`页码/源页 → 截图 → Taste 结果和依据 → Impeccable 结果和依据 → 问题/修复 → 确认结果`。
- 文字、数据、SKU、真实证据核验；不适用的网页项及原因；缺失工具、未执行检查和未解决问题。
- 总结：`通过 / 待修复 / 未完成审查`，不能只给一个没有依据的“95分”。

**放行**：每一交付页两套视觉审查均通过；全部原文/层级/数据/包装和输出完整性检查通过；已发现的缺陷已修正；确属不适用项有理由。审美偏好的可选建议应与真实缺陷分开。任何未解决漏字、遮挡、错 SKU、假证据、数据失真、空图或无法观看的最终输出都不得判通过。

若无法取得渲染或视觉读取能力，明确“画面终审未完成”。可以报告进度或按用户要求提供标明未审核的候选，不能称终稿、无问题或已完成双技能终审。该门槛规范 AI 的工作行为，不是能阻止所有 AI 绕过的系统级安全锁；`finalize.mjs` 等程序仍只验证其实现的技术检查。
