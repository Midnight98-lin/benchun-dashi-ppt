# Benchun Dashi PPT

当前确认版本：2026-09-09（v1.1.0：内置双技能终审；保留 Apple 风格编辑器与圆角调节）。后续生成与启动编辑器应使用本技能随附的运行文件，不回退到旧任务目录的编辑器副本。

本技能统一**视觉语言与制作方法，不统一业务内容或章节结构**。采用“HTML 演示 → 浏览器编辑与保存 → 导出 PPTX / PDF”的工作流；这是独立实现的品牌技能，不改动或复制原 `dashi-ppt` 的专有编辑器、API 与导出引擎。

## 先读什么

1. 有当前项目 `AGENTS.md` 时先读取，并按其要求检查项目知识与同步状态；没有本纯私有仓库时，使用本技能随附视觉规则和本次用户提供的资料，不猜测私有路径。不得因调用技能擅自归档或清理。
2. 阅读 `references/brand-system.md`、`references/production-gates.md` 和 `references/dual-review.md`。按双技能协议完整读取随包 Taste、Impeccable 入口及其适用参考，无须另行安装。涉及产品或证据图，再读 `references/asset-workflow.md`。
3. 看 `assets/reference-contact.jpg`，理解样张的主次、留白和构图，不照搬文案。公开版保留获准公开的品牌场景；证据页图片是显著标记的演示占位，必须替换为真实授权证据后才可用于实际文件。
4. 新任务使用当次提供的内容。只美化时，先提取原文：`python scripts/text_lock.py extract 原稿.pptx 工作目录/text-lock.json`。表格、脚注、单位、原本的大白话标题与专业解释一起锁定。图片中的文字另外核对。

## 优先级与范围

- 当次用户要求 > 项目正式品牌/资产规范 > 本技能。与通用技能冲突时，品牌要求优先；工具及安全约束不被覆盖。
- 不重写、缩写、替换原文，不把专业术语升为标题，不将正文降成脚注。字多时先调版式，再原文分页；是否允许分页以本次任务为准。
- 不强制固定页数、固定“产品—科学—使用方法”顺序或内容逻辑。视觉样张只示范版式，不作为产品事实来源。
- “本纯 PPT”默认本纯品牌色和版式库，无须再询问 12 套通用主题。未说明的媒介/页数，结合源稿和交付用途判断；仅询问会 materially 改变结果的缺项。
- 默认交付可离线打开、可编辑的 HTML 演示，并启动本地编辑器供浏览器编辑、保存与导出；按用户需要提供 PPTX / PDF，不把流程缩减为只交 PPTX。用户明确只要 PPTX 时可走仅 PPTX 交付，仍保留校核与源文件保护。

## 工作流

### 1. 明确简报并锁字

说明用途、受众、屏幕/阅读距离、源文件、是否允许分页、目标视觉、需要的包装规格。按项目设计角色：主智能体审定简报 → word_agent 提交逐页原文映射并锁字 → pic_agent 根据锁字和正式资产制作 → word_agent 核对文字 → 主智能体终审。不要启动无关部门。

没有可用或获准的子代理时，主 AI 依次完成以上角色工作并记录单 AI 执行；不得虚构代理参与，也不能因此省略锁字或双技能终审。

### 2. Taste → Impeccable → ImageGen

使用随包 `review-skills/design-taste-frontend/SKILL.md` 判断画面节奏和取舍，再用 `review-skills/impeccable/SKILL.md` 整理字阶、间距和对齐。必须按 `references/dual-review.md` 做 PPT 适配，不能因网页字数、标点、配色或技术栈规则改写原文、替换品牌或重构运行链路。涉及位图生成时阅读并使用当前环境的 `imagegen`（用户指定 im2 时使用当前可用对应生图工具，不声称已调用未实际调用的模型）。已有素材足够则不为凑流程生图；缺生图工具则说明，不能用假包装补位。

### 3. layout + props 编排

本技能保留 Dashi 的声明式编排思想；使用自己的 `benchun-*` 组件，不向原 Dashi 写入未登记的 theme13，也不混用它的 goal schema。

```text
node scripts/render.mjs --list
node scripts/render.mjs --inspect benchun-editorial
node scripts/render.mjs 工作目录/goal.json 工作目录/presentation
node scripts/serve.mjs 工作目录/presentation --port 5368
```

`assets/example.goal.json` 是可运行的十二类版式样张。复制到任务目录后填本次内容，不直接改技能内示例。具体字段见 `references/layouts.md`；颜色、字体和安全边距见 `assets/tokens.json`。支持 `benchun-hero`、`editorial`、`chapter`、`statement`、`rows`、`mechanism`、`flow`、`data`、`compare`、`evidence`、`montage`、`references`。

模板容量不足时拒绝截断或偷偷缩字。可以选择同族变体/调整版面/原文分页；必要时在任务副本扩展组件，再审查文字及几何。不要为了“每页不同”损害整套秩序，也不要连续三页使用相同剪影。

首次生成得到 `scene.json` 与独立 `index.html`；打开服务实际返回的 `127.0.0.1` 地址。浏览器可编辑文字、字体、位置尺寸、图片、表格和图表，也可改当前页底色、新增文字、插入图片、添加基本形状，以及复制、删除、调整对象前后层级和撤销/重做。文字、形状和图片共用右侧“自由变形”区，提供 PS 风格的九点参考位置、W/H 缩放百分比、比例锁定、八个拖动缩放控制点、中心旋转和水平/垂直翻转；文字缩放同步调整字号。矩形属于形状，不另设“色块”对象入口。新增与删除对象不构成助手改写原文、删除证据或正式资产的授权。

右侧“自由变换”默认以按钮收起，点击向画布侧展开浮动工具面板；点击外部、关闭按钮或 Escape 收起，切换对象/页面时自动收起。保留画布八个缩放控制点。

编辑器采用已确认的银白界面与森林绿重点色，保留左侧页面、中央画布、右侧属性的三栏结构；右侧按“样式／排列／页面”分类，次要设置折叠，配合克制轻动效。该界面样式仅用于编辑器，不强制改变幻灯片的品牌版式。选中圆角矩形后，在“样式 → 形状样式 → 圆角半径”通过滑块或数值输入调整，单位为 px；0 为直角，最大值为短边一半且不超过 360 px，修改纳入撤销、保存与导出。

在线模式自动保存并提供手动保存；查看保存状态、确认成功后再刷新或导出。编辑后以已保存的 `scene.json` 为主稿，不重跑旧 `goal.json` 覆盖人工修改。保留原始 goal、源稿和素材来源作为追溯依据。支持的图形、字体、自由变形及样式边界见 `references/runtime.md`，不要承诺透视扭曲、逐点变形、斜切、逐字富文本、任意图形或新增页面等未提供的功能。

离线 HTML 也可编辑，但浏览器不能直接写回原 HTML：必须下载编辑后的 HTML 保存，再打开下载文件核验。需要转入本地编辑器时导入到全新的演示目录，不覆盖原演示。运行、恢复与导出细节见 `references/runtime.md`。

### 4. 图像与数据

- 产品包装不得直接贴入版面、不得由 AI 重画标签；用确切原包装做保真二次渲染，融入环境光、透视、接触阴影和材质反射。先核对 SKU，再出图。100g、30g、罐体、管体、盒体不得互相替代。
- 图标与专业图解优先原生矢量形状/连接线，围绕原文解释作用关系。不要用一张通用毛囊大图代替所有专业内容。
- 数据来源、数值、单位、样本条件不变。量化信息使用原生可编辑图表/大数字/对比；不要用 3D 饼图制造视觉误差。专利与检测只用真实证据图片。

### 5. 导出与双技能终审

强制执行：按要求制作 → 保存并内部渲染/导出候选 → Taste 逐页画面审查 → Impeccable 逐页精修审查 → 集中修复与确认 → 通过后输出。具体范围、截图依据、限次修复、单 AI 降级与放行标准以 `references/dual-review.md` 为准。任务目录必须保留逐页双技能记录；未执行、未看图或未修复不许写“通过”。此为 AI 流程门槛，不将技术脚本误称完整视觉审查。

先浏览 HTML 全页检查；导出必须读取同一已保存 scene 的修订快照，不能重新排版旧 goal 或重新载入旧工作簿抹掉浏览器修改。本地编辑器提供 HTML 下载、演示与 PPTX / PDF 导出；离线 HTML 支持编辑、下载和打印 PDF，PPTX 导出需启动本地服务。

PPTX 使用 `@oai/artifact-tool` 输出原生文字、图形、图表和表格，保留新增图形、字体、斜体、下划线、旋转与翻转等对象样式，并必须经过 `finalize.mjs` 终检才可作为交付稿；不得以整页截图冒充可编辑 PPTX。使用 `--scene` 按同一导出修订的实际字体集检查，本地服务会自动传入。PDF 是静态打印版，不可编辑。HTML 与 PPTX 的字体、图表绘制、图片组合可能略有差异，必须核验最终文件；不承诺字体嵌入或跨设备无差异。本工具不是通用的浏览器 PPTX 导入编辑器。

导出后执行 `text_lock.py verify`；该检查只能证明可提取文本的保全，不能代替语义层级与视觉检查。若用户在浏览器明确修订文字或数据，保留原锁字记录并记录其授权变更，再按有效稿核对；编辑能力不构成助手自行改写授权。按 `presentations` 技能对最终 PPTX 执行包结构/字体/几何校验和逐页渲染；需要交付 PDF 时按 `pdf` 技能渲染检查。Taste 查整体视觉与多样性，Impeccable 查字阶/对齐/留白/溢出。逐页100%，关键包装与证据200%核验。发现漏字、截断、错 SKU、失真数据、假证据、线压字，必须修复再导出。交付前填写 `references/qa-checklist.md`；涉及新增对象、底色或文字样式时，另按 `references/qa.md` 核验。记录实际通过、失败和未执行项，不把有功能入口等同于通过测试。

## 输出与资产管理

每次新建任务目录；原稿不动。默认交付 HTML 演示、实际可用的本地编辑入口及保存说明，附用户要求的 PPTX / PDF；工作源 goal、已保存 scene、素材来源与 QA 记录留在任务目录。若服务未能启动或某种导出不可用，如实说明，不能提供失效入口或声称已验证。本技能只保留少量确认版视觉参考，不复制整个项目仓库。生成图片和候选稿不自动成为正式资产。安装技能不等于把所有样张、候选稿或业务内容确认归档。
